# Памятка для администраторов SOLOVYEV STORE

Краткая инструкция по работе с админ-панелью. Оплата на сайте не нужна: заказ фиксируется в системе, дальше общение и оплата идут в WhatsApp.

---

## 1. Вход

1. Откройте **секретный URL** админки (его даёт разработчик; публичный `/admin` для посторонних не открывается).
2. Введите логин и пароль администратора.
3. После входа слева — меню разделов, сверху — **Publish** (обновить кэш сайта) и **Logout**.

Не передавайте ссылку, логин и пароль клиентам. Сессия админа отдельна от кабинета покупателя (`/account`).

---

## 2. Карта разделов

| Раздел | Зачем |
|--------|--------|
| **Overview** | Сводка по сайту / аналитике |
| **Catalog** | Основной каталог товаров |
| **Made to order** | Товары под заказ |
| **Brand new** | Brand new / новые позиции |
| **Users** | Клиенты (аккаунты) |
| **Orders** | WhatsApp-заказы |
| **FAQ** | Вопросы–ответы на сайте |
| **Settings** | Контакты, валюта, анонсы, hero |
| **Analytics** | События: просмотры, корзина, checkout |

После правок каталога, FAQ или Settings нажмите **Publish**, чтобы изменения быстрее появились на витрине.

---

## 3. Каталог (типичный день)

1. **Catalog** → создать или открыть товар.
2. Заполнить название, цену, размеры, фото.
3. Выставить статус наличия, например:
   - **available** / **new_drop** — можно заказывать;
   - **reserved** — временно занят;
   - **sold** — продан, с витрины для покупки;
   - **draft** — черновик, не для публики.
4. Сохранить → **Publish**.

**Made to order** и **Brand new** — те же карточки, но в своих разделах.

Фото загружаются в хранилище проекта из формы товара. Без осмысленных фото и цены товар плохо работает в WhatsApp-заказе.

---

## 4. Как клиент делает заказ (важно понимать)

1. Клиент входит в аккаунт (email + пароль).
2. Жмёт заказ в WhatsApp (товар, Quick View или корзина).
3. Система **сначала создаёт заказ** с номером вида `SS-…`, **потом** открывает WhatsApp с готовым текстом.
4. В админке заказ появляется во вкладке **Orders**.

Если клиент не залогинен — его перенаправит на вход, а не «тихо» отправит в WhatsApp без записи в базе.

В сообщении WhatsApp обычно есть: номер заказа, товары, имя / телефон / email клиента (если заполнены в кабинете).

---

## 5. Orders — ведение заказа

### Список и фильтры

- Поиск по номеру заказа (`SS-…`) или email.
- Фильтр по статусу.
- Сводка за 7 / 30 / 90 дней (суммы = **сумма корзины при оформлении**, не обязательно уже оплаченные деньги).

### Карточка заказа

- Клиент (email, имя, телефон).
- Состав и subtotal.
- Смена **статуса** (сохраняется сразу).
- **Go to chat** — открывает WhatsApp-диалог **с клиентом** (не с номером магазина), с текстом про заказ `SS-…` и товары.
  - Работает только если у клиента есть телефон (снапшот при оформлении или в профиле `/account`).
  - Без телефона кнопка недоступна — попросите клиента указать номер в кабинете.

### Статусы (рекомендуемый порядок)

```
pending_whatsapp → in_chat → paid → shipped → completed
                                         ↘ cancelled
```

| Статус | Когда ставить |
|--------|----------------|
| **Pending WhatsApp** | Заказ только создан, клиент ещё не ответил / чат не начат |
| **In chat** | Переписка идёт, уточняете размер/наличие/доставку |
| **Paid** | Оплата подтверждена (вне сайта: перевод, наличные и т.п.) |
| **Shipped** | Отправлено / передано в доставку / клиент забрал по договорённости |
| **Completed** | Сделка закрыта |
| **Cancelled** | Отказ, нет товара, дубль и т.п. |

Старые заказы со статусом «Confirmed» в системе уже считаются как **In chat**.

### Чеклист менеджера по заказу

1. Открыть заказ → **Go to chat** (нужен телефон клиента; иначе найти по email вручную).
2. Статус → **In chat**.
3. Подтвердить наличие → при необходимости в **Catalog** поставить товар **reserved** / **sold**.
4. После оплаты → **Paid**.
5. После отправки → **Shipped**, затем **Completed**.
6. Если сорвалось → **Cancelled**, вернуть товар в **available**, если нужно.

> Сейчас смена статуса заказа **не меняет автоматически** статус товара в каталоге — это делается вручную в Catalog.

## 6. Users — клиенты

- Поиск по email или имени.
- Фильтр **Has orders** — только те, у кого уже были заказы.
- В карточке: контакты, маркетинг opt-in, счётчики заказов / избранного / корзины, последние заказы.

Телефон клиент может указать сам в `/account` — тогда он попадает в текст WhatsApp при следующем заказе.

**Marketing opt-in** — согласие на рекламные письма. Служебные письма (сброс пароля) идут независимо. Не используйте контакты без opt-in для рассылок.

---

## 7. Settings (что трогать осторожно)

- **WhatsApp phone** и **manager name** — от них зависят ссылки и приветствие в сообщениях заказа.
- Валюта, анонсы, Instagram, hero.
- После правок — **Publish**.

Неверный номер WhatsApp = клиенты уходят «в никуда».

---

## 8. FAQ и Analytics

- **FAQ** — тексты на сайте; после правок Publish.
- **Analytics** — события витрины (просмотры, корзина, begin checkout). Для операционной картины по заказам смотрите в первую очередь вкладку **Orders**.

---

## 9. Частые ситуации

| Ситуация | Что делать |
|----------|------------|
| Клиент пишет в WA, заказа в админке нет | Скорее всего заказал не через сайт или без входа. Попросите оформить снова через сайт после логина. |
| Go to chat недоступен | Нет телефона у клиента. Попросите сохранить номер в `/account` и/или найдите чат вручную. |
| Дубль заказа | Один оставьте в работе, второй → **Cancelled**. |
| Товар продали офлайн | В Catalog → **sold**, открытые заказы по нему закрыть/отменить и написать клиенту. |
| После правок на сайте «старое» | Нажать **Publish**, подождать минуту, обновить страницу с очисткой кэша. |

---

## 10. Чего в админке пока нет (не искать зря)

- Онлайн-оплата / счета PayPlus и т.п.
- Полноценный WhatsApp Business inbox внутри админки
- Входящие Sell/Trade как отдельный inbox (форма пока в основном ведёт в WhatsApp)
- Авторассылки, сегменты, CSV-экспорт клиентов
- Заметки по клиенту / трекинг-код / задачи менеджера в UI (поля в базе уже заложены, экран — позже)

---

## 11. Безопасность

- Не шарить админ-URL и пароль.
- Выходить через **Logout** на чужих компьютерах.
- Не править базу «вручную» в Supabase без необходимости — статусы заказов меняйте в **Orders**.

---

## 12. Кому писать, если сломалось

Если не логинится админка, не создаются заказы `SS-…`, Publish не обновляет сайт или падает загрузка фото — передайте разработчику: что делали, время, номер заказа / email клиента, скрин ошибки.

Миграции CRM / chat: `008_crm_foundation.sql`, `009_order_customer_phone.sql`.
