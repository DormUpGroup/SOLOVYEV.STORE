# Памятка для администраторов SOLOVYEV STORE

Краткая инструкция по работе с админ-панелью. Клиент оформляет заказ на сайте и платит картой через Grow. WhatsApp остаётся для Sell/Trade и вопросов.

---

## 1. Вход

1. Откройте **секретный URL** админки (его даёт разработчик; публичный `/admin` для посторонних не открывается).
2. На экране входа нажмите **Sign in** и введите логин и пароль.
3. После входа слева — меню по группам, сверху — **Refresh**, **Publish to site** и внизу sidebar — **View store** / **Log out**.

Не передавайте ссылку, логин и пароль клиентам. Сессия админа отдельна от личного кабинета покупателя (`/account`).

На телефоне меню открывается кнопкой ☰ слева вверху.

---

## 2. Карта разделов

Меню слева разбито на 4 группы:

### Store — товары
| Раздел | Зачем |
|--------|--------|
| **Catalog** | Основной каталог |
| **Made to order** | Товары под заказ (страница `/made-to-order`) |
| **Brand new** | Новинки (страница `/brand-new`) |

### Commerce — заказы и клиенты
| Раздел | Зачем |
|--------|--------|
| **Orders** | Заказы с сайта, статусы, оплата |
| **Users** | Клиенты (аккаунты на сайте) |
| **Reporting** | Отчёты, графики, PDF по продажам |

### Content — тексты и настройки
| Раздел | Зачем |
|--------|--------|
| **FAQ** | Вопросы–ответы на сайте |
| **Settings** | WhatsApp, Instagram, hero, контакты |

### Insights — аналитика
| Раздел | Зачем |
|--------|--------|
| **Overview** | Быстрая сводка: товары, GA, последние события |
| **Analytics** | GA4 + воронка магазина + график тренда |

**Важно:** после правок каталога, FAQ или Settings нажмите **Publish to site**, чтобы изменения быстрее появились на витрине.

## 3. Каталог (типичный день)

1. Откройте **Catalog** (или **Made to order** / **Brand new**).
2. Нажмите **Add product** (или **Add made-to-order item** / **Add brand-new item**).
3. Заполните название, цену, размеры, загрузите фото.
4. Выставьте статус:
   - **available** / **new_drop** — можно заказывать;
   - **reserved** — временно занят;
   - **sold** — продан;
   - **draft** — черновик, покупатели не видят.
5. Нажмите **Save** в форме товара.
6. Нажмите **Publish to site** сверху.

### Фото
- Загружаются прямо из карточки товара.
- Можно менять порядок (drag), кроп, поворот.
- Первое фото = главное на витрине.
- Справа есть **Live preview** — как будет выглядеть на сайте.

### Поиск и фильтры
- Строка **Search products…** и фильтр по бренду.
- Товары сгруппированы по бренду и категории.

## 4. Как клиент делает заказ

1. Клиент **входит в аккаунт** на сайте.
2. Жмёт checkout / Buy now.
3. На `/checkout` выбирает доставку и платит картой.
4. Система создаёт заказ `SS-…`, Grow списывает карту, статус становится **Paid**.

Если клиент не залогинен — его отправят на вход. Если оплата не настроена (нет вебхука Make) — на checkout будет ошибка, витрина работает как раньше.

### Включить оплату (Grow через Make)
1. Применить миграции `013_payplus_checkout.sql` (статусы `pending_payment`) и `014_grow_checkout.sql`. Только SQL, без полного `npm run setup:supabase`, если каталог уже в базе: `node scripts/apply-migration.mjs 014_grow_checkout.sql`.
2. В Make подключить приложение Grow: ת.ז или ח.פ и телефон аккаунта, не номер счёта. В сценарии вебхук создаёт payment link и отвечает сайту адресом страницы оплаты. Второе действие того же сценария подтверждает оплату (`action` = `approve`).
3. В `.env.local` / Vercel (Production + Preview): `MAKE_GROW_WEBHOOK_URL` и `MAKE_GROW_SECRET`. После этого — Redeploy.
4. Магазин — עוסק פטור: без НДС, клиент получает קבלה, не חשבונית מס. Номер עוסק в код не кладём.
5. Прямые `GROW_USER_ID` и `GROW_PAGE_CODE` нужны только если подключён платный API. Пока они пустые, сайт ходит в Make.
6. Чеклист для клиента: `docs/PAYMENT_PROVIDERS_CLIENT.md`.

## 5. Orders — ведение заказа

### Список
- Поиск по номеру `SS-…` или email.
- Фильтр по статусу.
- Переключатель **7 / 30 / 90 days** — сводка и график.
- Клик по строке → карточка заказа внизу.

### Карточка заказа
- Клиент, состав, сумма, доставка, last4 карты, id транзакции Grow.
- Смена **статуса** (сохраняется сразу).
- **Copy order ref** — скопировать `SS-…`.
- **Copy reply** / **Go to chat** — если нужно написать клиенту в WhatsApp.

### Статусы (рекомендуемый порядок)

```
Pending payment → Paid → Shipped → Completed
                              ↘ Cancelled
```

| Статус | Когда ставить |
|--------|----------------|
| **Pending payment** | Заказ создан, карта ещё не списана |
| **Pending WhatsApp** | Старые заказы до оплаты на сайте |
| **In chat** | Переписка (редко, для старых заказов) |
| **Paid** | Оплата прошла (ставится автоматически после Grow) |
| **Shipped** | Отправлено или передано клиенту |
| **Completed** | Сделка закрыта |
| **Cancelled** | Отмена, дубль, нет товара |

### Чеклист менеджера
1. Открыть заказ — проверить **Paid** и способ доставки (или написать в WhatsApp, если клиент сам написал).
2. В **Catalog** поставить **reserved** / **sold** при необходимости.
3. Отгрузить → **Shipped**, закрыть → **Completed**.
4. Если сорвалось → **Cancelled**, вернуть товар в **available**.

> Смена статуса заказа **не меняет автоматически** статус товара в каталоге.

### График в Orders
- Линия **Orders** — количество заказов по дням.
- Линия **Paid revenue** — выручка только по заказам со статусом **Paid**.

## 6. Reporting — отчёты

Раздел для обзора продаж без работы с отдельными заказами.

### Что внутри
- Переключатель **7 / 30 / 90 days**.
- Карточки: все заказы, выручка (paid), средний чек, число проданных позиций.
- **Orders by status** — круговая диаграмма: сколько заказов на каждом этапе.
- **Top products by revenue** — топ товаров по выручке (paid).
- Таблица топ-товаров с количеством и суммой.
- **Download PDF** — скачать PDF-отчёт за выбранный период.

**Revenue (paid)** — только заказы со статусом **Paid**, не сумма всех корзин.

---

## 7. Users — клиенты

- Поиск по email или имени.
- Фильтр **Has orders** — только с заказами.
- В карточке: контакты, marketing opt-in, заказы, избранное, корзина.

Телефон клиент может указать в `/account` — он нужен для 3D Secure при оплате картой.

**Marketing opt-in** — согласие на рекламные письма. Без него не используйте email для рассылок.

## 8. Settings (осторожно)

- **WhatsApp phone** и **manager name** — ссылки и текст в сообщениях заказа.
- Instagram, hero-фото, название магазина.
- После правок — **Publish to site**.

Неверный номер WhatsApp = клиенты уходят «в никуда».

## 9. Analytics — аналитика

### Google Analytics (если настроен)
- Realtime users, sessions, page views.
- Источники трафика и топ страниц.
- Смотрите **Overview** (кратко) или **Analytics** (подробно).

### Store funnel — воронка магазина
Три шага на сайте:
1. **Product views** — просмотры товара
2. **Add to cart** — добавления в корзину
3. **Checkout** — переход к оплате на сайте

График-воронка показывает, на каком шаге теряются клиенты. В tooltip — % конверсии между шагами.

### Trend
График просмотров / корзины / checkout по дням за выбранный период (7 / 30 / 90 days).

> Для операционной работы по заказам в первую очередь смотрите **Orders** и **Reporting**, а не Analytics.

## 11. Частые ситуации

| Ситуация | Что делать |
|----------|------------|
| Клиент пишет в WA, заказа нет | Попросить оформить через сайт после входа в аккаунт |
| Чат не находится по `SS-…` | Клиент ещё не отправил сообщение, или неверный номер в Settings |
| Дубль заказа | Один оставить, второй → **Cancelled** |
| Продали офлайн | **Catalog** → **sold**, открытые заказы закрыть/отменить |
| На сайте «старое» после правок | **Publish to site** → подождать минуту → Ctrl+F5 |
| Много pending, мало paid | Смотреть **Reporting → Orders by status**, работать с висящими заказами в **Orders** |
| Checkout: «Card payments are not configured» | Нет `MAKE_GROW_WEBHOOK_URL` на сервере |
| Заказ завис в **Pending payment** | Клиент не закончил оплату на странице Grow; можно отменить и вернуть товар в **available** |
| Оплата прошла, статус не Paid | Проверить callback URL в кабинете Grow и id транзакции в карточке заказа |

- Массовые рассылки и экспорт клиентов в CSV

## 13. Google Analytics — настройка (для разработчика)

Если GA не показывается, на сервере нужны:
- `GA4_PROPERTY_ID` — цифровой Property ID, не `G-…`
- `GA4_CLIENT_EMAIL` — email service account
- `GA4_PRIVATE_KEY` — private_key из JSON-ключа

Service account добавить в GA4 property с ролью **Viewer**, включить **Google Analytics Data API**.

---

## 14. Безопасность

- Не передавать админ-URL и пароль.
- **Log out** на чужих компьютерах.
- Статусы заказов менять в **Orders**, а не вручную в базе.

## 15. Если что-то сломалось

Напишите разработчику: что делали, время, номер заказа / email клиента, скрин ошибки.

Типичные проблемы: не логинится, не создаются заказы `SS-…`, Publish не обновляет сайт, не загружаются фото, оплата не переводит заказ в Paid.
